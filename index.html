01 / Why

Why put HTML activities in Rise.

Rise gives you nine native interaction types. HTML embed gives you the rest.

Rise is fast, responsive, and predictable. That predictability is also a ceiling. When a learning objective calls for an interaction Rise does not ship with, you have three honest options: rebuild in Storyline, send the learner away, or use the embed block. The third option keeps the learner in flow — and with AI assistance, it now takes minutes instead of hours.

01

Self-contained

One HTML file with inline CSS and JavaScript. No build step, no dependencies, no broken links three months later.

02

Sandboxed

The embed cannot reach back into Rise. That is a feature. No score returns to the LMS unless you build it intentionally.

03

Reusable

One pattern, many courses. Swap the content, keep the structure. Your team builds a library, not a backlog.

04

On-brand

You control the palette, the type, the spacing. The activity looks like part of the course, not bolted onto it.

02 / The Feature

Articulate Rise's "Add Code" block.

A small feature that opens a large door.

In Rise 360, the Embed block under Interactive blocks accepts a hosted URL or a paste-in Code Snippet. The Code Snippet option is what makes this workflow possible. You paste HTML, CSS, and JavaScript directly — no separate hosting required for simple, self-contained activities.

How to find it in Rise

  1. Open your Rise course and select the lesson where the activity should appear.
  2. Click Edit on the lesson, then click the + to add a new block.
  3. Choose the Interactive category, then select the Embed block.
  4. In the embed dialog, switch to the Code Snippet tab (instead of the URL tab).
  5. Paste your HTML code. Rise renders it inside an iframe automatically.
i
Two ways to get code into Rise.

Option A: Code Snippet — paste the entire HTML directly. Fastest for self-contained activities like the five in this showcase. Option B: URL — host the file elsewhere and paste the link. Better for activities that need to be updated centrally across many courses.

03 / Workflow

The five-step workflow.

From a learning need to a working activity in Rise. Repeatable every time.

01Familiarize

Know the Add Code feature

Open Rise. Find the Embed block under Interactive. Switch to the Code Snippet tab. Get comfortable with what Rise does — and does not — accept. (Self-contained HTML works; external script imports may be blocked by your tenant settings.)

02Prompt

Write the prompt

Describe the activity, the content, the design, and the behavior. Keep it specific. Include the UNT Health brand block in every prompt. Five reusable prompt templates are in the activity sections below.

03Generate

Generate with Claude

Paste the prompt into Claude. Claude returns a complete artifact with HTML, CSS, and JavaScript in a single file. Interact with the preview Claude shows you to confirm the behavior is right before copying.

04Copy & Paste

Copy the code into Rise

Use the Copy Code button on the artifact (or in this showcase, on the Step 2 code block of each activity). Paste it into Rise's Code Snippet tab. Set a sensible height. Save the block.

05Troubleshoot

Fix what's not working

If something looks off in Rise — colors are wrong, the layout breaks at narrow widths, a button does not respond — go back to Claude. Describe what is broken with the same level of specificity you used in the prompt. Claude will return an updated version. Paste the new code into Rise. See the troubleshooting section below for common cases.

1
Drag-to-Sort Categorizer
Move items into the correct bucket. Best for taxonomy, classification, or "which goes where" content.
Apply~3 min buildBest for taxonomy
When to use
Learners need to distinguish between categories: compliant vs. non-compliant, formative vs. summative, primary vs. secondary sources. The friction of placing the card is the cognitive work.
Design notes
Cap items at nine. Use 2–3 columns. On placement, color the card border Modern Green for correct, red for incorrect. Offer a reset button. Add a short rationale.
Common pitfalls
Drag-and-drop on touch is fragile. Always include a tap-to-select fallback (shown in the live example). Confirm focus order with keyboard.

Branching Scenario Card

A short situation, three choices, three consequences, a debrief.

2
Branching Scenario Card
A short situation, three choices, three consequences, a debrief.
Apply~4 min buildBest for judgment
When to use
The content is "it depends." You want learners to weigh trade-offs, not pick a memorized right answer. Patient communication, clinical judgment, ethics, conflict resolution.
Design notes
Keep the stem under 80 words. Each choice has a distinct consequence, not "right vs. wrong." Show the consequence, then a "Try a different choice" or "Continue to debrief" option.
Common pitfalls
Choices that are obviously bad. If one option is clearly the "trap," the activity becomes a quiz. Make each choice defensible.

Self-Check Knowledge Probe

Three to five questions, instant rationale, no score, no stakes.

3
Self-Check Knowledge Probe
Three to five questions, instant rationale, no score, no stakes.
RecallHighest reuse~2 min build
When to use
After a content block, before a section break, as a pulse-check. Rise has quiz blocks, but they feel formal. This feels like the course is talking to the learner.
Design notes
Show rationale for both correct and incorrect answers. The rationale is the teaching, not the score. Skip the running tally unless it adds value.
Common pitfalls
Treating it like a graded quiz. If you need a grade, use Rise's native quiz block. This pattern is for feedback, not assessment.

Build a single self-contained HTML file for a 3-question self-check on Bloom's revised taxonomy.

CONTENT
Q1: Which verb best matches the "Apply" level of Bloom's revised taxonomy?
  - Define / Use / Critique / Recall
  Correct: Use
  Rationale-correct: "Apply" means using learned material in new situations.
  Rationale-wrong: Define is Remember, Critique is Evaluate, Recall is Remember.

Q2: A learner can list the four cardinal directions. Which level is that?
  - Remember / Understand / Apply / Analyze
  Correct: Remember
  Rationale-correct: Listing from memory is the Remember level.
  Rationale-wrong: The verb "list" stays at Remember.

Q3: Which level: "Learners will compare two patient case studies and identify differences in care pathways"?
  - Understand / Apply / Analyze / Evaluate
  Correct: Analyze
  Rationale-correct: "Compare" and "identify differences" are Analyze verbs.
  Rationale-wrong: Compare-and-contrast tasks live at the Analyze level.

BEHAVIOR
- Show one question at a time.
- On selection, lock answers, highlight chosen answer with a #90C53D border if correct, #c0392b if incorrect.
- Show the matching rationale beneath.
- "Next question" advances. "Restart" at the end. No score display.

Hotspot Labeling
Click numbered hotspots on an image, then match them to labels. Includes drop-in image instructions.
Identify~4 min buildBest for visual content
When to use
The content is inherently visual: anatomy, equipment diagrams, screen layouts, charts, maps. Learners need to identify and name parts. The act of finding the right region on the image is part of the learning.
Design notes
Five to seven hotspots is the sweet spot. Use percentage-based positioning (not fixed pixels) so the image scales responsively. Shuffle the label panel order on each load so memorization across attempts is harder. Include a "Reset" button.
Common pitfalls
Fixed pixel positioning that breaks on mobile. Too many hotspots that overlap on small images. Labels that are too long for the panel. Forgetting to provide alt text on the image — a hotspot activity is inherently visual and needs accessibility care.
